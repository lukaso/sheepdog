## 0. Test containment (built first, in P0, before any destructive command exists)

Phase 2 adds paths that aim at processes sheepdog did not start in this run, through facts a test cannot fully contain (a journal left by an earlier run, responsibility, orphan status, the session). A test or a mutant must never reach this machine's real state or real processes. Five walls:

1. **The test tag and the latch (the wall for processes).**
   - **The tag.** The test environment (wall 4) carries `SHEEPDOG_TEST_TAG=<nonce>` (at least 64 random bits), so every process a test builds inherits it. A debug sheepdog reads its own tag at start.
   - **The latch.** A debug sheepdog has one process-wide, one-way latch. While it is on, **every** target the door signals is tag-checked; nothing ever turns it off. It starts **off**, and the **gate call** turns it on (**amended in P0, D1 below**). Every phase-2 source must hold the token that only the gate call makes, and the gate call turns the latch on **before** the source's first fact can enter any set that reaches the door: the sweep, the auto-sweep, a journal read in `kill <pid>` or `kill <job>`, a `pid:id` target, `--include-suspects`, `strays` and `strays --kill`, a registration accept. (Listing suspects without killing them sets nothing.)
   - **The phase-1 opt-out is structural.** `SHEEPDOG_TEST_PHASE1=1` starts the latch off **and disables every phase-2 source outright** in a debug build: no state, no journal, no auto-sweep, no suspects, no registration accept, no `pid:id`, no `strays`. So no source can ever run with the wall off, and the variable is safe to inherit by nested runs. It is for cells with a member that cannot carry a readable tag (an Apple platform binary; cell 9's `env -i` escapee). The list is made mechanically in P0: run the phase-1 suite with the latch on and no opt-out, and paste the red cells with the command. Checking the opt-out and setting the latch are **one gate call**, and each source must hold that call's token to reach the state resolver or the door; each step that adds a source adds its cell (disabled under the opt-out; control: enabled without it) and its mutant. Under the opt-out, registration means no listener and no `SHEEPDOG_OUTER` export. The own tag and the latch start lazily on first door use (`OnceLock`), so unit-test binaries get them too. The mechanical list also takes cells that stay green but write sink lines (each line attributed to its cell through the helper), and the P0 opt-out controls are on it by design; the unit-test list is made the same way (on macOS, e.g. `the_deadline_needs_two_empty_scans_without_an_authoritative_check`, `src/main.rs` ~1306). One helper sets the variable and asserts the cell is on the list; a grep shows it is spelled nowhere else. Unit tests that signal Apple binaries move to the fixture binary.
   - **The check.** The tag is read from the target's environment block (Linux `/proc/<pid>/environ`, after `pidfd_open` and before the identity re-read, so both describe the pinned process; macOS `KERN_PROCARGS2`), independent of the identity check. **The verdict is taken once per (pid, identity)**, before that target's first signal (on Linux pinned by the pidfd), and reused for every later signal to the same identity: the tag is a fact of the process's exec, and a re-read during `do_exit` (Linux: `environ` reads empty while the state is still R/D; macOS: `KERN_PROCARGS2` fails under `P_WEXIT`) would misclassify the CONT that follows a KILL. The whole `SHEEPDOG_TEST_TAG=<value>` entry must equal the door's own; a substring never matches. **If the door has no tag of its own**, every tag-checked target is withheld (a debug sheepdog outside the tests therefore cannot run a phase-2 source against anything). The block is the process's environment memory from exec: a process that `unsetenv`s stays tagged, but one that rewrites that memory (setproctitle-style) can erase it, which fails safe as a false `withheld`; one that execs with `env -i` loses it (so cell 9's `env -i` route cannot be swept in phase 2: a stated coverage limit).
   - **Three outcomes, none sends:** `withheld <pid> <sig>` (the block was read and has no matching tag); `unreadable <pid> <sig>` (a live process, identity unchanged, whose block could not be read); `gone <pid> <sig>` (the read failed and the identity is gone, or the state is Z/X, or the process is exiting: on Linux an empty block with no address space left, `/proc/<pid>/statm` all zero; on macOS `P_WEXIT` in `p_flag`). An empty block counts as `withheld` only while the process still has an address space. `gone` is normal in a kill; a `withheld` or `unreadable` line fails a cell, except the one line a wall-control cell expects.
   - **Consequences for cells.** Every process in a phase-2 cell is built from binaries whose block can be read: the test fixture binary, and Homebrew's `node` and `python3` (a precondition reads their tag). macOS cannot read an Apple platform binary's block (`/bin/sleep`, `/bin/sh`, `/usr/bin/python3`), so those are never members in a phase-2 cell. Decoys carry the tag, so a mutant's red is the decoy's own counter; the tag only keeps the operator's processes out of reach. A stress cell: a 50-member sweep through the full STOP, KILL, CONT sequence, 20 times, 0 `withheld`/`unreadable` lines; the members include some that exit by themselves during the pass. Wall controls: one target with an empty environment and one with a non-empty untagged one. Mutants: an empty read is always `withheld` (the stress cell goes red); re-read the tag for each signal, made deterministic by a seam that makes any read after the first signal return empty.
2. **The state wall.** A debug build ignores `SHEEPDOG_STATE`, `XDG_STATE_HOME` and `HOME` for state. It uses only `SHEEPDOG_TEST_STATE`, and only if that directory holds the sentinel `.sheepdog-test`. Otherwise: no journal, no sweep, no auto-sweep, and a `state-unset` trace (in the trace file, not the signal log). The state resolver is a pure function of an injected environment.
3. **One signal door.** Every signal sheepdog sends goes through one function that applies the inert seam, the identity check and the tag check, including `kill_tree`'s panic path (`src/main.rs` ~478 today calls `libc::kill` directly). The other sites, from `grep -n 'libc::kill(\|pidfd_send_signal\|libc::raise\|killpg\|\.kill()' src/*.rs` at 7d75d04: `main.rs` 258, 270, 308 are the door itself; `main.rs` 1323, 1386–1451 are in `#[cfg(test)]`; `main.rs` 1006/1014/1125 CONT the relay this supervisor forked; `macos.rs` 470–491 and `linux.rs` 341–375 are the relay signalling the supervisor that forked it; `macos.rs` 793/806 KILL/CONT the root this supervisor spawned; `libc::raise` (main.rs 792, 1166, 1220; macos.rs 515; linux.rs 298) signals sheepdog itself. Each gets a one-line comment naming its target; phase 2 adds no site outside the door; each review re-runs the grep and classifies every hit.
4. **The test environment.** A cargo `runner` (`.cargo/config.toml`, `scripts/test-env`) starts every **test binary** (one whose parent directory is `deps` under the active target directory, `$CARGO_TARGET_DIR` or `target`, so `/tgt/debug/deps/…` in the Linux legs; anything else, such as `cargo run`, is exec'd unchanged and gets no tag) with the environment already set, so no spawn in any cell can precede it. It forks the binary, forwards TERM and INT to it, waits, passes the child's exit status or signal through to cargo, and after it exits checks that the canary state directory is still empty and that the withheld sink (below) is empty, failing the run otherwise; each check has a control cell (a nested run with the sentinel planted in the canary writes there, and the check goes red). It adopts `SHEEPDOG_LEG_TAG` if `test-all` set one (so a leg's pre-started processes share it), and never an inherited `SHEEPDOG_TEST_TAG`; otherwise it makes a fresh tag. Every `withheld`/`unreadable` line is also written to a sink file named by `SHEEPDOG_TEST_SINK` (the run sink by default), so a cell without its own signal log cannot hide one. One grep-able helper may point a wall-control cell's spawns at a sink the cell owns; the cell asserts exactly one line there; the runner checks only the run sink (mutant: the helper writes to the run sink, and the run goes red). The canary and sink checks are proved by driving the runner as a subject (a fixture binary through `scripts/test-env`, a non-zero exit expected), never by a cell inside the suite. The other-user leg runs each binary through `scripts/test-env` too. It removes every other `SHEEPDOG_*` and `XDG_STATE_HOME` from the test binary's own environment, sets `SHEEPDOG_TEST_STATE` to a canary directory without a sentinel (so an unconfigured nested debug run has no state), and puts first on `PATH` a directory holding a `sheepdog` symlink to the debug binary. So every descendant, including the ~25 sites that start sheepdog through `/bin/sh -c`, `Held::start`, `Pty` and the fixture's exec modes, finds the debug build and inherits the tag. A `Once` in every helper only asserts the variables are present. `sd()` in `tests/common` is the direct spawn helper; it gives each **cell** (not each spawn) a fresh `SHEEPDOG_TEST_STATE` with its sentinel, so a cell's `run` and `sweep` share state. The shell legs in `test-all` and `scripts/*.sh` export the same variables. Test binaries assert `cfg!(debug_assertions)` at entry. The P0 commit pastes the spawn-site count before and after: `grep -rn 'sheepdog()' tests | wc -l`.
5. **Release builds refuse a test environment.** A release build that sees `SHEEPDOG_TEST_TAG` or `SHEEPDOG_TEST_STATE` exits 125 before it reads state or sends a signal. The cells that run a release binary (this one, and phase 3's cell 18 and the distribution cell) build it with `cargo build --release` into the leg's own target directory, and run it with `HOME`, `XDG_STATE_HOME` and `SHEEPDOG_STATE` all set to a fresh temp directory, `--no-sweep`, and the command `true`; so the mutant "release ignores the test environment" reaches only that temp directory.

**P0 builds the mechanisms and tests them on what exists today:** the door, the latch, the structural opt-out and its mechanical list, the runner, and a debug seam that forces the latch on (`SHEEPDOG_TEST_LATCH=1`). With the seam, on the existing `kill_tree` panic path (`panic_after_stop`): an untagged built process (spawned with a cleared environment) in `known` gets `withheld` and its counter stays 0, while a tagged one dies (control); the state resolver with injected environments (the operator's `SHEEPDOG_STATE` exported, no sentinel, sentinel present); a nested `sheepdog` in a fixture script leaves a debug trace; the release refusal. A debug run with a cleared environment (no own tag) and the latch forced on withholds an untagged target. Without the seam: a tagged debug `kill <pid>` of an untagged built process gets `withheld` (the latch is on from start); control: the same run with the opt-out kills it. One-way: the seam turns the latch on mid-run in an opt-out process, then an untagged target is withheld. The gate call with the opt-out set returns no token (a unit cell); the per-source cells come with each source. Mutants: the latch starts off in a tagged process; the opt-out honoured without being set; a later call turns the latch off; the gate returns a token under the opt-out; the panic path around the door; the seam does not reach the panic path; the tag read from the caller instead of the target; two absent tags compare equal; honour `SHEEPDOG_STATE` in debug; release ignores the test environment.

**Each wall's live control is written red in the step that adds the first path that could breach it,** with a mutant that unwires the wall: P1 (the state wall: the operator's `SHEEPDOG_STATE` exported to a planted directory stays untouched; positive control, a journal exists mid-run under `SHEEPDOG_TEST_STATE`), P4 (sweep, auto-sweep, `kill <job>`, the journal in `kill <pid>`: an untagged built process named in a journal with its correct identity gets `withheld`; the tag check with the identity re-check removed: a journaled pid reused by an untagged built process still gets `withheld`), P4 also `kill pid:id`; P5 (registration: an untagged registrant, given the socket path and nonce by argv, whose accepted registration would make an untagged decoy a member: `withheld`); P6 (suspects); P7 (`strays --kill`).

**The test-made terminal T.** Cells that depend on responsibility (the spoof, every `--inherit-terminal-permissions` cell including cells 2, 3 and 12 in that mode, the other-tab cell, any mutant of R) are launched by T, a test-made fixture spawned disclaimed so that it is responsible for itself, and all its descendants carry the tag. Preconditions, each a red if false (never a skip): a probe child spawned by T reports `responsible == T`; each decoy's responsible process is T; in `--inherit-terminal-permissions` mode, a post-check once the supervisor runs: its responsible process is T (a red if not; the cell kills its tree by recorded identity). P6's suspect cells run in a test-made session (T under `setsid`), so the session link reaches only test processes.

**The protected-folder probe** (D10) has a debug seam that forces EPERM for a named path; automatic legs never open a real protected folder. Real protected folders are only in the manual tcc leg.

## 1. Decisions (settled here; say so in review if one is wrong)

1. **State directory** (release): `$SHEEPDOG_STATE`, else `$XDG_STATE_HOME/sheepdog`, else `~/.local/state/sheepdog`, on both OSes (debug: §0.1). Created 0700; journals 0600 (they hold capped argv, which can hold secrets). Path: `$STATE/jobs/<boot-id>-<pidns>/<job-id>.journal`.
   - **Checks before any sweep read:** the state dir, `jobs/` and the boot folder are owned by the euid and not group- or other-writable; otherwise `sweep` refuses (exit 1) and the auto-sweep skips with a note. Journals are opened read-only with `O_NOFOLLOW`, and `fstat` must show the euid as owner before the sweeper takes the lock or reopens the file for append; the reopened fd is `fstat`ed against the locked inode. A failed closure append (EACCES, ENOSPC) does not skip the job: the sweep goes on to signal and adds a note, as decision 2. A bind-mounted state dir owned by another uid (root in a container) makes every auto-sweep skip with a note: stated.
   - A same-uid forger is out of scope (it can signal the victim directly).
2. **The journal never stops the job.** No HOME, a read-only filesystem, ENOSPC, a failing `flock` or `link`: the job runs and is killed exactly as in phase 1. If the lock fails, no journal is published. A failed write never delays or prevents a signal. One warning, a `journal-failed` trace, and a `notes` entry; the exit code is unchanged. A failed auto-sweep is a note, never an error.
3. **Boot id:** Linux `/proc/sys/kernel/random/boot_id`; macOS `kern.bootsessionuuid`. **Pid namespace:** Linux `<dev>.<ino>` of `/proc/self/ns/pid`; macOS `0`. The folder only narrows what is read; a later container may reuse an nsfs inode, so the fence is the identity re-check.
4. **Job id:** `j-` + 8 random hex digits (`getentropy`). **`j-` is required on input and always printed**, so a bare number is always a pid. A prefix of at least 4 hex digits after `j-` is accepted; lookup covers the current boot/pidns folder; an ambiguous prefix is refused (exit 2) with the candidates listed.
5. **Owner tag:** `--owner NAME`, default `default` (PLAN §3.5). The header records it. The auto-sweep sweeps only journals with the run's own owner tag; `sweep` takes `--owner X` (default `default`); `--no-sweep` skips the auto-sweep.
6. **Journal format and lifecycle:**
   - JSON lines, `"v": 1`. **Header:** boot id, pidns, owner tag, owner uid, the supervisor's pid and identity (start time on Linux, uniqueid on macOS, as `ident.rs`), its argv (capped), the root's pid and identity.
   - **One complete JSON object per member per line**, `{"pid", "id", "ppid", "pid_id", "puniq", "cmd"}` (`pid_id` = the parent's identity; `puniq` = macOS `p_puniqueid`, absent on Linux; so a subtree can be derived on both OSes, including a macOS double-fork escapee whose ppid is launchd at first sight). The header's root `cmd` comes from sheepdog's own arguments, never from `/proc` (the shim). All the lines of one scan go in one `write`. The member count is never capped; only `cmd` is (256 bytes, non-UTF-8 escaped `\xHH`). A short write is completed by a further write. The reader acts only on complete, newline-terminated lines that parse; a partial last line loses at most the members on it.
   - **The root is journaled before it runs:** macOS: the job id is fixed by publishing (below) after the re-exec and before the root's environment is built, and the root's line is written before the resuming CONT; Linux: before the shim's go byte (decision 7).
   - Publishing: create a temp name (0600, `O_EXCL`), take `flock LOCK_EX` (after the SETEXEC, CLOEXEC), write the header, and only then `link` the temp to the final name (so no reader sees a published file without its header) (atomic no-replace on every filesystem; EEXIST picks a new id), unlink the temp. A file with no header, or a temp name, is ignored by readers; `sweep` deletes temp files older than a day whose lock it can take.
   - Each scan: one write, before any signal to that scan's new members.
   - Clean end: unlink, then release the lock. A sweeper re-checks, after it takes the lock, that the path still names the inode it locked.
   - `leave-strays` is written only when the root ends by itself, so a leave-strays job that is SIGKILLed mid-run is still swept. Stated: a SIGKILL between the root's end and that write is swept too. `sweep` deletes a leave-strays journal once none of its members is alive.
   - After exit 125 the journal stays; the next sweep takes it. Other boots' folders (compared on the boot-id part of the name only, so a live container's folder of this boot is never one): `sweep` deletes one only when it holds no file younger than 30 days; the auto-sweep never reads them.
7. **Linux root spawn (for the pipe and PDEATHSIG).** `posix_spawn` stays (no Rust code runs in a forked child). It spawns sheepdog's own binary in a hidden `__root` mode:
   - **Its own path:** resolved once at start: `/proc/self/exe`, unless it names a translator (Rosetta, `qemu-*`, as `exe_name` already detects), then `getauxval(AT_EXECFN)` made absolute at start (never argv[0], which the caller controls). Without a translator the shim is spawned as the literal `/proc/self/exe`, so an in-place upgrade or a deleted binary does not break it. The shim answers a handshake carrying the build id before the go byte, within a 5 s deadline (a cold Rosetta or qemu start), so a wrong binary is caught as `not-started`. P1 probes this on the amd64 leg before building, and an amd64 cell runs a job through the shim.
   - **The command's path** is searched by the shim itself, in its own process (no TOCTOU), by the POSIX rules written out, since no libc exports a search-only call and `execvp` differs from `posix_spawnp` (glibc `execvp` retries ENOEXEC through `/bin/sh`): a name with `/` is `execve`d as is; otherwise each PATH element in turn (an empty element is the cwd; an unset PATH is the libc's default, `confstr(_CS_PATH)` or musl's, whichever phase 1's `posix_spawnp` used, measured); ENOENT/ENOTDIR (and, as glibc does, ESTALE/ENODEV/ETIMEDOUT) go on, EACCES is remembered and goes on, any other error stops; at the end a remembered EACCES wins over ENOENT. No `/bin/sh` fallback. The errno goes on the CLOEXEC error pipe; the supervisor maps ENOENT to 127 and every other error to 126, as phase 1 does. Cells, each compared with phase 1 on Alpine and Debian: no shebang line, EACCES-then-found, an empty element, an unset PATH.
   - **The attr** blocks every signal (`setsigmask` full) and sets the dispositions to default as today; the caller's mask travels in the shim's argv (hex), never in the environment.
   - **The shim**, dispatched in `main` before `setup_signals` and before anything else: sets `PR_SET_PDEATHSIG(SIGKILL)`; checks `getppid()` is the supervisor; reads one go byte (EOF = the supervisor died); sets the go and error fds CLOEXEC; restores the caller's mask as its **last** step; then `execve`s (the cell: a script with no shebang line exits with the code phase 1 gives today, measured before the change, on Debian and Alpine). A failed `prctl`, a wrong parent or EOF: the shim writes a reason to the error pipe and `_exit`s without exec; the supervisor reports `root: "not-started"` and exits 125 (never 127, which means "not found").
   - **The supervisor** never blocks on the error pipe: it is read in the event loop, so a ctrl-Z or ctrl-C during the shim's window is handled as today. A signal sent to the shim before exec stays pending while all are blocked; when the shim restores the caller's mask, a pending unblocked signal is delivered **to the shim**, just before `execve` (a ctrl-C kills it by default INT, a TSTP stops it). Stated; the cell: a ctrl-C in the window (seam holds the shim) reports the root as `signaled`, never `not-started` or 127.
   - The pipe fds and the lock fd never reach the command (the lock is taken after the spawn; the pipes are CLOEXEC before exec).
   - `is_sheepdog` does not treat a `__root` shim as a supervisor; the leftover patterns in `test-all` and `scripts/linux-suite.sh` include `__root` shims and nested sheepdogs started through the test PATH symlink.
   - **Nested supervisors:** a `sheepdog run` that starts with an inherited non-zero PDEATHSIG replaces it with `PR_SET_PDEATHSIG(SIGTERM)` (never 0; the rule the supervisor already applies to its relay, `linux.rs` ~296), so SIGKILL to an outer supervisor becomes an orderly TERM kill of the inner job. A run whose PDEATHSIG is 0 sets none (`nohup sheepdog run &` is unchanged). Stated: only an inner run that is the outer's command itself (exec'd by the shim, directly or through `exec`) inherits the setting; one a shell forks as a child inherits none (Linux clears it on fork), so the outer's SIGKILL leaves it running as a live job, and an explicit `sweep` ends it (measured: dash forks its last command, BusyBox execs it). Cell (Linux): SIGKILL the outer while the inner root still runs; the inner supervisor TERM-kills its escapee (signal log) and dies of TERM. Mutant: clear to 0 (the inner job lives; the cell's watchdog fires). Stated: an inner run stopped by the outer's freeze when the outer is SIGKILLed holds its TERM pending, so the auto-sweep defers it and an explicit `sweep` ends it; a caller that ignores TERM gets no parent-death kill of the inner job (PLAN §4.1).
   - Cells 23 and every phase-1 exit-code cell are the regression. Stated: PDEATHSIG is cleared by a setuid or file-capability exec, and fires on the parent thread's exit (sheepdog is single-threaded). Because the root dies with the supervisor, PLAN §3.5's Linux sweep loses the root's children born after the last scan (they go to init): **PLAN §3.5 amended**, as the trade-off its "narrows this" names.
8. **`--status-fd` / `--status-file`:** PLAN §3.1's schema plus: `notes: [...]`; `job` with `j-`; `root: "not-started"` when the root never ran; `trigger_at` in ms since start; `tracking: "none"` for Linux `--mode none`; `killed[].escaped` from the closed set `null | "setsid" | "reparented" | "registered" | "puniq"`, derived from the fact that proved it. The file is written to a temp name and renamed. A usage error in `--status-fd` itself writes nothing and exits 125.
9. **Memory for `--max-mem`:** macOS `ri_phys_footprint`; Linux `smaps_rollup` Pss (PLAN §3.4 amended), falling back to `statm` RSS with a note. Read only when `--max-mem` is set.
10. **Caps within a tick** (PLAN §3.1 amended by this decision): every tick evaluates the timeout, then `--max-mem`, then `--max-procs`, in `Running` and in `Ending`. The first to fire is `trigger` and sets exit 124 — **unless the root had already ended by itself**: a cap first firing after that is a `notes` entry only, and the exit code is the command's. A later cap after the trigger is a `notes` entry.
11. **`kill <job>`:**
    - It passes `kill`'s target checks first: a job whose supervisor is sheepdog's own ancestor or the caller's shell is refused (exit 1).
    - Live supervisor (pid and identity match the header): TERM + CONT to it, wait grace + deadline, as `kill <supervisor pid>`. A stopped supervisor gets the CONT. A supervisor that has not ended by then: exit 125, the supervisor is left alone, and the line says so (no escalation). **Corrected in P4c:** `kill <supervisor pid>` does not do that (phase 1 goes on to kill the proved set, the supervisor included); `kill <job>` does, because a supervisor that still runs guards its own job's escapees, which this kill cannot prove on macOS.
    - Dead supervisor (gone, or its pid reused): sweep that one job with the full sweep rules (§3, explicit mode).
    - Unknown id: exit 1. Ambiguous prefix: exit 2. Otherwise `kill`'s codes (0/1/125).
    - Every use of the header's pid (kill, `ps`, the "runs under" line, `strays`' job marking, the live-job test) re-checks its identity.
12. **The journal in `kill <pid>`** proves only the target itself (it was a member of a dead job) and what the journal's `ppid`/`pid_id` lineage derives as the target's own subtree; never the rest of the job (D14). The output names the job: `sheepdog kill j-…`. The read takes the job's lock and follows every sweep fence.
13. **Registration** follows PLAN §3.2 (SHEEPDOG_OUTER chain, `mkdtemp` socket, `LOCAL_PEERTOKEN` read after the record, `pidversion` before and after the membership check, one ack byte, 2 s budget, 16-entry cap). Reads are non-blocking and multiplexed in the loop, with a 100 ms deadline per connection and a cap on pending connections. macOS only; Linux needs none.
14. **Output modes:** `ps`, `strays` and `kill` print a table on a tty, the same columns without color when piped, one JSON object per line with `--json`. Each subcommand's exit codes and its usage error (exit 2) are built in the step that adds it.

## 3. Sweep rules (sweep, the auto-sweep, and `kill <job>` of a dead job)

1. Read only the current boot/pidns folder, after the ownership checks. Only journals with the requested owner tag (the run's own tag for the auto-sweep). Skip a file whose lock is held (a live job, or any lock error) or whose journal marks leave-strays.
2. Candidates: the journaled members whose identity still matches, plus the live closure from them (Linux: the ppid closure; macOS: the `puniq` closure, PLAN §3.5). **Holding the lock, the sweeper appends every closure candidate to the journal before its first signal** (first writing a `\n` if the file does not end in one, so a partial last line never swallows its first append), so a candidate that survives a partial pass or a 125 is still named for the next one.
3. **Never** sheepdog itself, its ancestors or the caller's shell: the same protected filter and fail-closed ancestor walk as `kill`. A job that contains one is **skipped whole**, a note names the job and the protected pid, the journal is kept.
4. **Explicit mode** (`sweep`, `kill <job>`): a candidate that is a sheepdog supervisor is ended first (TERM + CONT, wait its grace + deadline). Then STOP the rest, re-check identity, KILL, CONT, within the kill deadline.
5. **Auto mode:** a candidate named in a journal in the same folder whose lock is held (a live job journals its members before it signals them) is left alone. A live supervisor among the candidates, and its set, is left alone too. Its set is every candidate whose macOS responsible process is that supervisor, or whose journaled lineage (`ppid`/`pid_id`, and `puniq` through journaled dead ids) reaches it; on Linux the ppid closure plus the journaled lineage. Anything whose live lineage reaches a deferred candidate is deferred too. The sweeper's own locked journal (by inode) is never read as a live job; explicit mode does not use the locked-journal rule, because it ends a live supervisor first. That set is deferred to an explicit `sweep` (a note names it); the rest of the job is swept. For the rest: no grace; STOP, re-check, KILL, CONT, with a short deadline (500 ms, counted from the start of the pass, so the closure scan and the tag reads are inside it). **PLAN §3.5 amended:** "bounded to 200 ms" becomes "200 ms between passes, at most 500 ms over", and a live inner supervisor's subtree waits for an explicit `sweep`. A pass that misses its deadline CONTs everything it stopped that is still alive, keeps the journal, and adds `partial` to `notes`. The 200 ms budget is checked between journals; with the short deadline, one pass overruns it by at most 500 ms (stated in the help).
6. Unlink the journal only when every candidate is gone. The sweeper's lock fds are CLOEXEC and closed before the new root spawns.
7. **Where the auto-sweep runs:** after the macOS re-exec (so once); on Linux before the relay fork; in both, before the pre-spawn TERM check. A TERM during the sweep lets the current pass finish, then sheepdog exits without spawning.

## 4. Risks, named now

- **Destructive commands on processes sheepdog did not start in this run.** Identity is re-checked before every signal; the boot and pidns folders narrow the read; a live job's lock fences it off; the ancestor rule protects the caller; the ownership checks keep other users' files out; the owner tag keeps other callers' jobs out. Tests reach none of this machine's real state or processes (§0).
- **nsfs inode reuse:** the identity re-check is the fence.
- **Registration is a security boundary on macOS:** the kernel names the peer; nothing in the record is trusted except the nonce; the peer must already be a member.
- **`--max-mem` samples every 250 ms:** a job can overshoot between samples. Stated in the help.
- **The auto-sweep runs before every job:** at most one pass overruns the budget, by at most 500 ms.

## 4a. Amendments made while building

- **D1 (P0, 2026-09-28): the latch starts off; the gate call turns it on.** Measured on this Mac before building: the environment block of `/bin/sh`, `/bin/bash`, `/bin/zsh` and `/bin/sleep` cannot be read by a same-uid process (`ps eww` shows none of a planted variable), while Homebrew's `python3` and `node`, `/usr/bin/python3` and our own binaries show it. With the latch on from start, nearly every macOS phase-1 cell (about 150 spawn sites use `/bin/sh` or `/bin/sleep`) would have to be on the opt-out list, so the list would be the norm, not the exception. The safety the "on from start" rule bought (review 4, N1: a mutant that moves a phase-2 fact into a phase-1 set) is kept by the token: a phase-2 fact can only come from a source, a source cannot run without the token, and the only thing that makes a token is the gate call, which sets the latch first (and returns none under the opt-out). A source that reads nothing (an auto-sweep over an empty state directory) produces no fact; it takes the token when it opens its first journal. `--inherit-terminal-permissions` is a source (it widens R). The latch is one-way by construction: it is an `AtomicBool` that the code only ever stores `true` into, so no cell tests a "turn it off" call that does not exist. P0's cells test the latch through the debug seam `SHEEPDOG_TEST_LATCH=1` and the gate call in unit tests; each later step adds the cell and mutant for its own source. The opt-out list is then empty in P0 and grows only when a step's source runs in a phase-1 cell with an unreadable member.
