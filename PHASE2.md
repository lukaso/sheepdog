## 0. Test containment (built first, in P0, before any destructive command exists)

Phase 2 adds commands that aim at processes sheepdog did not start in this run, through facts a test cannot fully contain (a journal left by an earlier run, responsibility, orphan status). A test or a mutant must never reach this machine's real state or real processes. Four walls, all in debug builds:

1. **The state wall.** A debug build ignores `SHEEPDOG_STATE`, `XDG_STATE_HOME` and `HOME` for state. It uses only `SHEEPDOG_TEST_STATE`, and only if that directory holds the sentinel file `.sheepdog-test` that the test helper creates. Otherwise: no journal, no sweep, no auto-sweep, and a `state-unset` trace. A **release** build that sees `SHEEPDOG_TEST_STATE` in its environment refuses to run (exit 125), so a release binary that a test reaches by mistake is loud, not destructive.
2. **Default withhold.** In a debug build, every signal from `sweep`, the auto-sweep, `kill <job>`, `strays --kill` and the registration path is **withheld unless `SHEEPDOG_TEST_ALLOW` is set**. When it is set, it names a file of `pid:identity` lines; a real signal goes only to a listed pair. Every other target gets a `withheld <pid> <sig>` line in the signal log and no signal. Phase-1 paths (`run`'s own job, `kill <pid>`) keep today's behaviour and the inert seam.
3. **One signal door.** Every signal sheepdog sends in production goes through one function that applies the inert seam, the allowlist and the identity check, **including `kill_tree`'s panic path** (`src/main.rs` ~478 today calls `libc::kill` directly). The remaining raw sites, from `grep -n 'libc::kill(' src/*.rs` at 177ae28 (23 lines): `main.rs` 1386–1432 are in `#[cfg(test)]`; `main.rs` 1006/1014/1125 CONT the relay this supervisor spawned; `macos.rs` 470–491 and `linux.rs` 341–375 are the relay signalling its own parent supervisor; `macos.rs` 793/806 KILL/CONT the root this supervisor spawned. Each gets a one-line comment naming its target; phase 2 adds no raw site, and each review re-runs that grep.
4. **One spawn helper and a test PATH.** `tests/common` gets `sd()`, the only way a test starts sheepdog. It builds the command from the absolute debug binary, removes `SHEEPDOG_STATE`, `XDG_STATE_HOME`, `SHEEPDOG_OUTER`, `SHEEPDOG_TEST_ALLOW` and every other `SHEEPDOG_*` from the inherited environment, sets a fresh `SHEEPDOG_TEST_STATE` (with its sentinel), and puts first on `PATH` a directory holding a `sheepdog` symlink to the debug binary, so a nested `sheepdog` in a fixture script is the debug build. All existing spawn sites move to it (`grep -rn 'CARGO_BIN_EXE_sheepdog' tests` = 8 bindings at 177ae28; each binding's `Command::new` uses are rewritten; the P0 commit pastes the before and after counts). The shell legs in `test-all` and `scripts/*.sh` export the same variables. The test binaries assert `cfg!(debug_assertions)` at entry.

**P0 cells:**
- control for (1): `SHEEPDOG_STATE` is exported to a real-looking directory holding a planted dead journal that names a live built decoy with its correct identity; a debug run writes nothing there, the `state-unset` trace appears, and the decoy's own counter stays 0. Positive control in the same shape: with `SHEEPDOG_TEST_STATE` set, a journal file exists while the job runs.
- control for (2): an auto-sweep with no allowlist over a journal that names a live built decoy with its correct identity: a `withheld` line names the decoy, its counter is 0. With the allowlist naming it: it dies.
- control for (3): a panic seam in a sweep pass with an unlisted built decoy in `known`: a `withheld` line (red against today's panic path).
- a nested `sheepdog` in a fixture script leaves a debug trace (proof it is the debug build); a release build with `SHEEPDOG_TEST_STATE` set exits 125.
- mutants: honour the inherited `SHEEPDOG_STATE`; default send when the allowlist is unset; panic path around the door; release build ignores `SHEEPDOG_TEST_STATE`.

**Allowlists in `run`-mode cells.** Where the correct code must kill its own members (spoof, other tab, registration), every fixture process appends its own `pid:identity` to the allowlist before it escapes or signals ready, and every decoy records itself in a separate decoy file. Red is "a `withheld` line naming a pid in the decoy file". A `withheld` line naming a pid in neither file fails the cell as a harness error.

**The test-made terminal T.** Cells that depend on responsibility (the spoof, every `--inherit-terminal-permissions` cell including cells 2, 3 and 12 in that mode, any mutant of R) are launched by T, a test-made process the fixture spawns disclaimed so that it is responsible for itself. Before acting, the cell asserts `responsible(T) == T` and `responsible(sheepdog) == T`; if either fails, the cell aborts without running sheepdog. These cells also run under the allowlist.

**The protected-folder probe** (D10) has a debug seam that forces EPERM for a named path; automatic legs never open a real protected folder. Real protected folders are only in the manual tcc leg.

## 1. Decisions (settled here; say so in review if one is wrong)

1. **State directory** (release): `$SHEEPDOG_STATE`, else `$XDG_STATE_HOME/sheepdog`, else `~/.local/state/sheepdog`, on both OSes (debug: §0.1). Created 0700; journals 0600 (they hold capped argv, which can hold secrets). Path: `$STATE/jobs/<boot-id>-<pidns>/<job-id>.journal`.
   - **Checks before any sweep read:** the state dir, `jobs/` and the boot folder are owned by the euid and not group- or other-writable; otherwise `sweep` refuses (exit 1) and the auto-sweep skips with a note. Journals are opened `O_NOFOLLOW` and `fstat` must show the euid as owner. A bind-mounted state dir owned by another uid (root in a container) makes every auto-sweep skip with a note: stated.
   - A same-uid forger is out of scope (it can signal the victim directly).
2. **The journal never stops the job.** No HOME, a read-only filesystem, ENOSPC, a failing `flock` or `link`: the job runs and is killed exactly as in phase 1. If the lock fails, no journal is published. A failed write never delays or prevents a signal. One warning, a `journal-failed` trace, and a `notes` entry; the exit code is unchanged. A failed auto-sweep is a note, never an error.
3. **Boot id:** Linux `/proc/sys/kernel/random/boot_id`; macOS `kern.bootsessionuuid`. **Pid namespace:** Linux `<dev>.<ino>` of `/proc/self/ns/pid`; macOS `0`. The folder only narrows what is read; a later container may reuse an nsfs inode, so the fence is the identity re-check.
4. **Job id:** `j-` + 8 random hex digits (`getentropy`). **`j-` is required on input and always printed**, so a bare number is always a pid. A prefix of at least 4 hex digits after `j-` is accepted; lookup covers the current boot/pidns folder; an ambiguous prefix is refused (exit 2) with the candidates listed.
5. **Owner tag:** `--owner NAME`, default `default` (PLAN §3.5). The header records it. The auto-sweep sweeps only journals with the run's own owner tag; `sweep` takes `--owner X` (default `default`); `--no-sweep` skips the auto-sweep.
6. **Journal format and lifecycle:**
   - JSON lines, `"v": 1`. **Header:** boot id, pidns, owner tag, owner uid, the supervisor's pid and identity (start time on Linux, uniqueid on macOS, as `ident.rs`), its argv (capped), the root's pid and identity.
   - **One complete JSON object per member per line**, `{"pid", "id", "ppid", "pid_id", "cmd"}` (`pid_id` = the parent's identity, so a subtree can be derived). All the lines of one scan go in one `write`. The member count is never capped; only `cmd` is (256 bytes, non-UTF-8 escaped `\xHH`). A short write is completed by a further write. The reader acts only on complete, newline-terminated lines that parse; a partial last line loses at most the members on it.
   - **The root is journaled before it runs:** macOS before the resuming CONT; Linux before the shim's go byte (decision 7).
   - Publishing: create a temp name (0600, `O_EXCL`), take `flock LOCK_EX` (after the SETEXEC, CLOEXEC), write the header, `link` the temp to the final name (atomic no-replace on every filesystem; EEXIST picks a new id), unlink the temp. A file with no header, or a temp name, is ignored by readers; `sweep` deletes temp files older than a day whose lock it can take.
   - Each scan: one write, before any signal to that scan's new members.
   - Clean end: unlink, then release the lock. A sweeper re-checks, after it takes the lock, that the path still names the inode it locked.
   - `leave-strays` is written only when the root ends by itself, so a leave-strays job that is SIGKILLed mid-run is still swept. `sweep` deletes a leave-strays journal once none of its members is alive.
   - After exit 125 the journal stays; the next sweep takes it. Other boots' folders: `sweep` deletes one only when it holds no file younger than 30 days; the auto-sweep never reads them.
7. **Linux root spawn (for the pipe and PDEATHSIG).** `posix_spawn` stays (no Rust code runs in a forked child). It spawns sheepdog's own binary (`/proc/self/exe`) in a hidden `__root` mode, which: sets `PR_SET_PDEATHSIG(SIGKILL)`; checks `getppid()` is the supervisor (else `_exit(127)` without exec); reads one go byte from a pipe (EOF = the supervisor died: `_exit` without exec); sets the go fd and the error-pipe fd CLOEXEC; restores the caller's mask and dispositions (as cell 23 requires); `execvp`s the command. An exec failure writes errno to the CLOEXEC error pipe, so the supervisor still reports 126/127 and `root: "not-started"`. The pipe fds and the lock fd never reach the command (the lock is taken after the spawn; the pipes are CLOEXEC before exec). Cells 23 and every phase-1 exit-code cell are the regression. Stated: PDEATHSIG is cleared by a setuid or file-capability exec, and fires on the parent thread's exit (sheepdog is single-threaded).
8. **`--status-fd` / `--status-file`:** PLAN §3.1's schema plus: `notes: [...]`; `job` with `j-`; `root: "not-started"` when the root never ran; `trigger_at` in ms since start; `tracking: "none"` for Linux `--mode none`; `killed[].escaped` from the closed set `null | "setsid" | "reparented" | "registered" | "puniq"`, derived from the fact that proved it. The file is written to a temp name and renamed. A usage error in `--status-fd` itself writes nothing and exits 125.
9. **Memory for `--max-mem`:** macOS `ri_phys_footprint`; Linux `smaps_rollup` Pss (PLAN §3.4 amended), falling back to `statm` RSS with a note. Read only when `--max-mem` is set.
10. **Caps within a tick:** every tick evaluates the timeout, then `--max-mem`, then `--max-procs`, in `Running` and in `Ending`. The first to fire is `trigger` and sets exit 124 — **unless the root had already ended by itself**: a cap first firing after that is a `notes` entry only, and the exit code is the command's. A later cap after the trigger is a `notes` entry.
11. **`kill <job>`:**
    - It passes `kill`'s target checks first: a job whose supervisor is sheepdog's own ancestor or the caller's shell is refused (exit 1).
    - Live supervisor (pid and identity match the header): TERM + CONT to it, wait grace + deadline, as `kill <supervisor pid>`. A stopped supervisor gets the CONT. A supervisor that has not ended by then: exit 125, the supervisor is left alone, and the line says so (the same rule as `kill <supervisor pid>` today; no escalation).
    - Dead supervisor (gone, or its pid reused): sweep that one job with the full sweep rules (§3, explicit mode).
    - Unknown id: exit 1. Ambiguous prefix: exit 2. Otherwise `kill`'s codes (0/1/125).
    - Every use of the header's pid (kill, `ps`, the "runs under" line, `strays`' job marking, the live-job test) re-checks its identity.
12. **The journal in `kill <pid>`** proves only the target itself (it was a member of a dead job) and what the journal's `ppid`/`pid_id` lineage derives as the target's own subtree; never the rest of the job (D14). The output names the job: `sheepdog kill j-…`. The read takes the job's lock and follows every sweep fence.
13. **Registration** follows PLAN §3.2 (SHEEPDOG_OUTER chain, `mkdtemp` socket, `LOCAL_PEERTOKEN` read after the record, `pidversion` before and after the membership check, one ack byte, 2 s budget, 16-entry cap). Reads are non-blocking and multiplexed in the loop, with a 100 ms deadline per connection and a cap on pending connections. macOS only; Linux needs none.
14. **Output modes:** `ps`, `strays` and `kill` print a table on a tty, the same columns without color when piped, one JSON object per line with `--json`. Each subcommand's exit codes and its usage error (exit 2) are built in the step that adds it.

## 3. Sweep rules (sweep, the auto-sweep, and `kill <job>` of a dead job)

1. Read only the current boot/pidns folder, after the ownership checks. Only journals with the requested owner tag (the run's own tag for the auto-sweep). Skip a file whose lock is held (a live job, or any lock error) or whose journal marks leave-strays.
2. Candidates: the journaled members whose identity still matches, plus the live closure from them (Linux: the ppid closure; macOS: the `puniq` closure, PLAN §3.5).
3. **Never** sheepdog itself, its ancestors or the caller's shell: the same protected filter and fail-closed ancestor walk as `kill`. A job that contains one is **skipped whole**, a note names the job and the protected pid, the journal is kept.
4. **Explicit mode** (`sweep`, `kill <job>`): a candidate that is a sheepdog supervisor is ended first (TERM + CONT, wait its grace + deadline). Then STOP the rest, re-check identity, KILL, CONT, within the kill deadline.
5. **Auto mode:** a job whose candidates include a live supervisor is deferred to an explicit `sweep` (a note names it). Otherwise: no grace; STOP, re-check, KILL, CONT, with a short deadline (500 ms). A pass that misses its deadline CONTs everything it stopped that is still alive, keeps the journal, and adds `partial` to `notes`. The 200 ms budget is checked between journals; with the short deadline, one pass overruns it by at most 500 ms (stated in the help).
6. Unlink the journal only when every candidate is gone.
7. **Where the auto-sweep runs:** after the macOS re-exec (so once), before the pre-spawn TERM check. A TERM during the sweep lets the current pass finish, then sheepdog exits without spawning.

## 4. Risks, named now

- **Destructive commands on processes sheepdog did not start in this run.** Identity is re-checked before every signal; the boot and pidns folders narrow the read; a live job's lock fences it off; the ancestor rule protects the caller; the ownership checks keep other users' files out; the owner tag keeps other callers' jobs out. Tests reach none of this machine's real state or processes (§0).
- **nsfs inode reuse:** the identity re-check is the fence.
- **Registration is a security boundary on macOS:** the kernel names the peer; nothing in the record is trusted except the nonce; the peer must already be a member.
- **`--max-mem` samples every 250 ms:** a job can overshoot between samples. Stated in the help.
- **The auto-sweep runs before every job:** at most one pass overruns the budget, by at most 500 ms.
