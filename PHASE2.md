**What phase 1 taught, applied here from the start:**
- every shape runs contained (`Held`, or a test-made shell in its own group);
- a control cell for every absence check (an empty log, a zero count);

- a cell that the kernel can satisfy on its own (orphaned-group HUP+CONT, reaping by launchd) is not evidence;
- review each fix commit as its own diff; parallel reviewers each get their own scratch directory.

## 0. Test containment for phase 2 (built first, in P1, before any destructive command exists)

Phase 2 adds commands that aim at processes sheepdog did not start in this run (`sweep`, the auto-sweep, `kill <job>`, `strays --kill`) and aim through facts a test cannot fully contain (responsibility, orphan status). Two walls, both debug-build only:

1. **The state wall.** In a debug build, sheepdog uses a state directory only when `SHEEPDOG_STATE` names it. Without it: no journal, no sweep, no auto-sweep, one `notes` entry (`state: unset`). So no test and no mutant can ever read or sweep `~/.local/state/sheepdog`. The test spawn helper (`tests/common/mod.rs`) gives every test its own temp `SHEEPDOG_STATE`; the shell legs in `test-all` do the same. Control cell: a debug run without `SHEEPDOG_STATE` whose root leaves a member journal-worthy writes no file under a temp `HOME`/`XDG_STATE_HOME` and reports the note.
2. **The signal allowlist.** `SHEEPDOG_TEST_ALLOW=<file>` holds `pid:identity` lines the test wrote. When it is set, `send_checked` sends a real signal only to a listed pair, and writes `withheld <pid> <sig>` to the signal log for every other target. Every cell that runs `sweep`, `kill <job>`, `strays --kill`, the registration spoof or the other-tab cell sets it. A mutant's red for these cells is a `withheld` line naming a pid outside the list, so a mutant can never reach an unbuilt process. Control cell: a listed decoy and an unlisted decoy, both told to die; the listed one dies, the unlisted one's own counter stays 0 and a `withheld` line names it. The existing inert seam stays for the phase-1 cells.

The "terminal" in the spoof and other-tab cells is a test-made process that the fixture makes responsible for itself (a disclaimed spawn) and that spawns the decoys; the real terminal app is never the responsible process a cell aims at. Every `strays` cell adds `--cmd <unique marker>`.

## 1. Decisions (settled here; say so in review if one is wrong)

1. **State directory:** `$SHEEPDOG_STATE`, else `$XDG_STATE_HOME/sheepdog`, else `~/.local/state/sheepdog`, on both OSes (debug builds: `$SHEEPDOG_STATE` only, §0). Created 0700. The journal path is `$STATE/jobs/<boot-id>-<pidns>/<job-id>.journal` (PLAN §3.5).
   - **Checks before any read for sweep:** the state dir, `jobs/` and the boot folder are owned by the euid and not group- or other-writable; otherwise sweep refuses (one line, exit 1) and the auto-sweep skips with a note. Journals are opened `O_NOFOLLOW`, and `fstat` must show the euid as owner.
   - A same-uid forger is out of scope (it can signal the victim's processes directly).
2. **The journal never stops the job.** No HOME, a read-only filesystem, ENOSPC, or a `flock` that fails (ENOLCK/EOPNOTSUPP on network filesystems): the job runs and is killed exactly as in phase 1. If the lock fails, no journal is published (never an unlocked one). A failed write never delays or prevents a signal. The run gets one warning line and a `notes` entry, and `degraded` stays about membership only; the exit code is unchanged. A failed auto-sweep is a note, never an error.
3. **Boot id:** Linux `/proc/sys/kernel/random/boot_id`; macOS `kern.bootsessionuuid`. **Pid namespace:** Linux the device and inode of `/proc/self/ns/pid` (`<dev>.<ino>`); macOS a constant `0`. The folder only narrows what is read; nsfs inodes may be reused by a later container, so the fence is the identity re-check (§3).
4. **Job id:** `j-` + 8 random hex digits (from `getentropy`). **`j-` is required on input and always printed**, so a bare number is always a pid (PLAN §3.0). A prefix of at least 4 hex digits after `j-` is accepted; lookup covers the current boot/pidns folder only; an ambiguous prefix is refused (exit 2) with the candidates listed.
5. **Journal format and lifecycle:**
   - JSON lines, `"v": 1`. **Header:** boot id, pidns, owner uid, the supervisor's pid, identity (start time), argv (capped), and the root's pid and identity. Then one line per scan: `{"pid", "id", "cmd"}` for each member first seen in that scan.
   - `cmd` is capped at 256 bytes; non-UTF-8 bytes are escaped (`\xHH`). A short write is retried. The reader acts only on complete, newline-terminated lines that parse; a partial last line never yields a pid.
   - **The root is journaled before it runs:** on macOS before the resuming CONT; on Linux the child waits on a pipe until the supervisor has written the root's line, then execs.
   - Order: create a temp name, take `flock LOCK_EX` (after the SETEXEC, CLOEXEC), write the header, rename with no-replace (`renameat2(RENAME_NOREPLACE)` / `renamex_np(RENAME_EXCL)`; a collision picks a new id). A file with no header, or a temp name, is ignored by readers.
   - Each scan: one write, before any signal to that scan's new members.
   - Clean end: unlink, then release the lock. A sweeper re-checks, after it takes the lock, that the path still names the inode it locked.
   - `leave-strays` is written to the journal only when the root ends by itself, so a leave-strays job that is SIGKILLed mid-run is still swept.
   - After exit 125 the journal stays (the kill did not finish); the next sweep takes it. The auto-sweep reads only the current boot/pidns folder, so other-boot folders never slow it; `sweep` lists them and `doctor` counts them; nothing deletes another boot's folder.
6. **`--status-fd` / `--status-file`:** PLAN §3.1's schema plus: `notes: [...]`; `job` with `j-`; `root: "not-started"` when the root never ran (126/127, TERM before spawn); `trigger_at` in milliseconds since the start; `tracking: "none"` for Linux `--mode none`; `killed[].escaped` from a closed set `null | "setsid" | "reparented" | "registered" | "puniq"`, derived from the fact that proved it. The file is written to a temp name and renamed. A usage error in `--status-fd` itself writes nothing to any fd and exits 125.
7. **Memory for `--max-mem`:** macOS `proc_pid_rusage(RUSAGE_INFO_V4).ri_phys_footprint`; Linux `smaps_rollup` Pss (shared and copy-on-write pages counted once), falling back to `statm` RSS with a note when it is missing. Read only when `--max-mem` is set. Sum over live members at each tick.
8. **Caps within a tick:** every tick, in `Running` and in `Ending`, evaluates the timeout, then `--max-mem`, then `--max-procs`. The first to fire is `trigger`; any later one goes to `notes`.
9. **`kill <job>`:**
   - Live supervisor (pid and identity match the header): TERM + CONT to it, wait grace + deadline, as `kill <supervisor pid>` does today. A stopped supervisor gets the CONT.
   - Dead supervisor (gone, or its pid reused: identity mismatch): sweep that one job, with the full sweep rules (§3).
   - Unknown id: exit 1. Ambiguous prefix: exit 2. Exit codes otherwise as `kill <pid>` (0/1/125).
   - Every use of the header's pid (kill, `ps`, the "runs under" line, `strays`' job marking, the live-job test) re-checks its identity.
10. **Registration** follows PLAN §3.2 (SHEEPDOG_OUTER chain, `mkdtemp` socket, `LOCAL_PEERTOKEN` read after the record, `pidversion` before and after the membership check, one ack byte, 2 s budget, 16-entry cap). Reads are non-blocking and multiplexed in the loop, with a 100 ms deadline per connection and a cap on pending connections, so silent clients cannot stall enforcement. macOS only; Linux needs none (the subreaper chain).
11. **Output modes:** `ps`, `strays` and `kill` print a table on a tty, the same columns without color when piped, and one JSON object per line with `--json` (PLAN §10.5). Each subcommand's exit codes and its usage error (exit 2) are built in the step that adds the subcommand.

## 3. Sweep rules (sweep, the auto-sweep, and `kill <job>` of a dead job)

1. Read only the current boot/pidns folder, after the ownership checks (§1 decision 1). Skip a file whose lock is held (a live job) or whose header marks leave-strays.
2. For each journal: the candidates are the journaled pids whose identity still matches, plus their live ppid children.
3. **Never** sheepdog itself, its ancestors or the caller's shell: the same protected filter and fail-closed ancestor walk as `kill`. A job that contains one of them is **skipped whole**, with a warning naming the job and the protected pid; its journal is kept.
4. A candidate that is a sheepdog supervisor is ended first (TERM + CONT, wait its grace + deadline), as `kill` does.
5. Then STOP the rest, re-check identity, KILL, CONT. A pass for one journal is never cut in the middle: the auto-sweep's 200 ms budget is checked only between journals, so it can overrun by one pass (stated in the help). Out of budget → `partial`, the rest waits for the next run.
6. Unlink the journal only when every candidate is gone.
7. **Where the auto-sweep runs:** after the macOS re-exec (so once), before the pre-spawn TERM check. A TERM during the sweep lets the pass finish, then sheepdog exits without spawning.

## 4. Risks, named now

- **`sweep`, `kill <job>` and `strays --kill` are destructive on processes sheepdog did not start in this run.** Identity is re-checked before every signal; the boot and pidns folders narrow the read; a live job's lock fences it off; the ancestor rule protects the caller; the ownership checks keep another user's journals out. Tests reach none of this machine's real state or processes (§0).
- **nsfs inode reuse:** a new container may get a dead container's pidns inode. The folder then mixes two namespaces; the identity re-check is the fence.
- **Registration is a security boundary on macOS:** the kernel names the peer; nothing in the record is trusted except the nonce; the peer must already be a member by the scan's own function.
- **`--max-mem` samples every 250 ms:** a job can overshoot between samples (cell 13's bound allows for it). Stated in the help.
- **The auto-sweep runs before every job:** a pass can overrun its budget by one journal (§3.5).
