# sheepdog — phase 2 build plan

**Status:** draft for review (2026-09-27). Nothing is built.

**Phase-2 scope (PLAN.md §7):** caps (`--timeout`, `--max-mem`, `--max-procs`), `--status-fd` / `--status-file`, the journal, job ids, registration (macOS), `sweep` and the auto-sweep, `ps`, `kill <job>`, suspects in `kill <pid>` (`--include-suspects`), `strays`, `doctor`, `--inherit-terminal-permissions`; cells 13–15, 17, 19, 25, 26, 28 (suspects), 29–31; safety cells: registration spoof, a non-member registers, `--inherit-terminal-permissions` other tab, the journal cells (wrong identity, other boot, other pid namespace).

**Carried in from phase 1** (PHASE1.md): the full kill report (§10.4; phase 1 prints only errors, the deadline report and the D9 hint); cell 22′(h) (a pid-only INT, then SIGKILL to the sheepdog pid, then `sweep` finds the journaled members; it needs `sweep`); the "runs under" line names the supervisor pid until job ids exist (it then names the job); the CLI surface of §10.5 (the help screen, usage errors exit 2 for every subcommand but `run`, `--version`, output modes).

**Not in phase 2:** the release packaging and signing, the TCC symlink check (phase 3), adoption (phase 4).

**What phase 1 taught, applied here from the start:**
- every cell aimed at a process it did not build runs under the inert seam, and every shape runs contained (`Held`, or a test-made shell in its own group) — `sweep` and `strays --kill` are the two commands that aim at processes sheepdog did not start;
- a control cell for every absence check (an empty log, a zero count);
- no pinned text: cells read the debug signal log, exit codes, `--status-fd` JSON, or `--json` output;
- a cell that the kernel can satisfy on its own (orphaned-group HUP+CONT, reaping by launchd) is not evidence;
- review each fix commit as its own diff; parallel reviewers each get their own scratch directory.

## 1. Decisions (settled here; say so in review if one is wrong)

1. **State directory:** `$SHEEPDOG_STATE`, else `$XDG_STATE_HOME/sheepdog`, else `~/.local/state/sheepdog`, on both OSes. Created 0700. The journal path is `$STATE/jobs/<boot-id>-<pidns>/<job-id>.journal` (PLAN §3.5).
2. **Boot id:** Linux `/proc/sys/kernel/random/boot_id`; macOS `kern.bootsessionuuid`. **Pid namespace:** Linux the inode of `/proc/self/ns/pid`; macOS a constant `0`.
3. **Job id:** `j-` + 8 random hex digits (from `getentropy`), unique in its boot/namespace directory (retry on collision). Every command that takes a job accepts any unique prefix of at least 4 hex digits, `j-` optional; a bare number is always a pid (PLAN §3.0).
4. **Journal format:** a header line, then one line per scan (JSON lines, `"v": 1`): `{"pid", "id", "cmd"}` for each member first seen in that scan. One `write(2)` per scan, before any signal to that scan's new members (PLAN §3.5).
5. **`--status-fd` / `--status-file`:** exactly PLAN §3.1's schema, written once at the end. The fd is set CLOEXEC after the SETEXEC.
6. **Memory for `--max-mem`:** macOS `proc_pid_rusage(RUSAGE_INFO_V4).ri_phys_footprint`; Linux `statm` resident × page size. Sum over live members at each 250 ms tick.
7. **Registration** follows PLAN §3.2 as written (SHEEPDOG_OUTER chain, `mkdtemp` socket, `LOCAL_PEERTOKEN` read after the record, `pidversion` before and after the membership check, one ack byte, 2 s budget). macOS only; Linux needs none (the subreaper chain).
8. **Output modes:** `ps`, `strays` and `kill` print a table on a tty, the same columns without color when piped, and one JSON object per line with `--json` (PLAN §10.5).

**Reviews:** after P1 (the journal is the base of every destructive phase-2 command), after P4 (`sweep` is the first command that kills processes of a job that is no longer supervised), after P5 (registration is a security boundary), after P7 (`strays --kill` aims at processes of any origin), and after P10 (the phase-2 review). Each continues until a round changes nothing.

**Exit rules, every step** (as in phase 1): `./test-all` green on every automatic leg; every new cell seen red first; every mutant built, run and red for its stated reason; no cell acts on a fixed sleep where readiness is available; cleanup only by recorded identity or marker; every shape contained.

## 3. Risks, named now

- **`sweep` and `strays --kill` are destructive on processes sheepdog did not start in this run.** Identity is re-checked before every signal, as in `kill`; the journal's boot id and pid namespace fence off other boots and containers; a live job's lock fences it off. Every cell that aims at a decoy runs under the inert seam or checks the decoy's own signal counter.
- **Registration is a security boundary on macOS:** the kernel names the peer; nothing in the record is trusted except the nonce; the peer must already be a member by the scan's own function.
- **`--max-mem` samples every 250 ms:** a job can overshoot between samples (cell 13's bound, 1 GB against a 500 MB cap at 50 MB/s, allows for it). Stated in the help.
- **The auto-sweep runs before every job:** its 200 ms budget and its guards must hold, or every `sheepdog run` pays for a slow sweep.
